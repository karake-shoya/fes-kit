# 実機確認25項目の仕分け（E2Eの射程を決める）

作成 2026-08-08。対象は `.claude/docs/TODO.md` の「Shoya の実機確認待ち①〜⑤」。
（`.claude/` は gitignore（`.gitignore:43`）なので、版管理する文書はこの `docs/` に置く。）

## なぜ作ったか

feskit は 2026-07-29 から止まっている。止まっている理由は「次に何をやるべきか分からない」ではない。
**やることは25項目あり、その全部が「Shoya にしか確認できない」で詰まっている。**
Clerk 認証後の画面を preview ツールで開けないため、Claude はこれらの画面を一度も見ていない。

つまり feskit の律速は**着手ではなく検証**にある。ここを機械に渡さないと、実装を足すほど未検証の在庫が増える。
この文書は、E2E を書く前に「**どこまで機械が肩代わりできるか**」を実測で確定させるためのもの。

## 結論

| 区分 | 件数 | 意味 |
|---|---:|---|
| **A：E2Eで機械が判定できる** | 20 | DOM・テキスト・数値・スタイルで合否が決まる |
| **B：E2Eで判定できるが条件つき** | 5 | touch エミュレーション／WebKit エンジン／AI応答のモックが要る |
| **C：実機でしか確認できない** | **0** | — |

**25項目すべてが E2E の射程内。** 事前の想定（「見た目系は実機でしか無理」）は、実装を読んだ結果くつがえった。

ただし **E2E はブラウザエンジンであって実機ではない**。iOS Safari 固有の描画差は残る。
正しい運用はこう分ける：**見た目は初回だけ実機で見て、以後の回帰を E2E が守る。**
初回さえ通れば、同じ項目を毎回目視する必要はなくなる。

## 区分の定義

- **A**：`expect(locator)` で真偽が確定する。人の目を必要としない。
- **B**：Playwright の設定（`hasTouch`・`webkit` プロジェクト）か、外部応答のモックが前提になる。設定さえ済めば判定自体は A と同じ。
- **C**：実機（iPhone・PWA インストール状態）でしか再現できない。

## E2Eの初期スコープ（この順で書く）

費用対効果の高い順。**上3つで25項目のうち12件が閉じる。**

1. **③5「これにする」の1往復**（③5・③3・③1）— `applyScenario` は商品を書き換える唯一の経路なのに、実データで1回しか通っていない
2. **①4 6種ダイアログ**（①4）— 共通シェルに載せ替えた退行がここに集中する
3. **②4・④4 数値の一致**（②4・②5・④4・④2）— 画面から読んで比べるだけで、人がやると最も間違えやすい
4. ①1・①2・①3（描画とオフライン）
5. ②1〜②3・③2〜③6・④1〜④5・⑤1〜⑤5

## 着手の前提（順序3で片づける）

- **Clerk のテストユーザー**：`clerk-testing` の手順で、テストモードの固定コードユーザーを1人用意する。鍵の配置は Shoya のみ。**鍵が要る作業はこの1回にまとめる**（Slack の User Token が 2026-08-05 から止まったままなのと同じ形を作らない）
- **Playwright の設定**：`hasTouch: true`（スワイプ）と `webkit` プロジェクト（⑤2）を最初から入れる。後から足すと B の5件が宙に浮く
- **CI との関係**：`.github/workflows/ci.yml`（lint・test・build）は E2E と別物で、鍵なしで動く。E2E は鍵が要るので別ジョブに分ける

### 🟢 E2E の宛先は Vercel のプレビューURLでよい（2026-08-08 に判明）

PR #25 で CI を初稼働させたとき、**Vercel が PR ごとにプレビューをデプロイしている**ことが分かった。
例：`https://fes-kit-git-<ブランチ名>-karake-shoyas-projects.vercel.app`

E2E がアプリを自前でビルド・起動する必要はなく、**このURLに当てればよい**。

### 🔴 ただし先に決める：プレビューが見ている DB

プレビューは Vercel の環境変数を使うので、**本番と同じ Turso を指している可能性が高い**。
E2E は商品の値段や作る予定数を実際に書き換える（③5「これにする」がまさにそれ）ので、
**このまま走らせると本番データを汚す。** E2E 着手前に次のどれかを決めること：

1. Vercel の Preview 環境だけ `TURSO_DATABASE_URL` を別DBに向ける（最も素直）
2. E2E 専用のプロジェクトを毎回作って最後に消す（データは混ざるが痕跡は残らない）
3. E2E は CI 内でアプリを起動し、ローカルの `file:` DB を使う（プレビューを使わない）

**推奨は1。** 2は「消し忘れたら汚れる」形なので、村で潰したはずの「人が覚えておく運用」に戻る。

なお **Vercel の Deployment Protection が有効だとプレビューに認証が挟まる**ので、
その場合は Protection Bypass トークンが要る。鍵をまとめる1回にこれも含める。
